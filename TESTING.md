# PlexonKeys staging checklist

Run this on a staging copy before enabling real economy or crate rewards. Compilation and MockBukkit tests target Paper 26.2; actual external-plugin behavior must be checked with your server's installed versions.

1. **Startup:** Start Paper 26.2 with Java 25 and the built jar. Confirm PlexonKeys enables, creates `config.yml` and `plexonkeys.db`, and `/keysadmin status` works. Check there are no severe log errors.
2. **Key binding:** Hold a real crate key with its display name, lore, custom model data, enchantments, attributes, and external PDC/NBT. Capture it, restart normally, give yourself one virtual key, and claim it. Compare its item data (apart from count) and redeem it with the actual crate plugin. Repeat for all four categories.
3. **Natural vs placed:** Temporarily set Basic mining/logging to 100% and other category chances to zero. Break natural stone and naturally generated logs: each appropriate action should add one. Place the same materials and break them: no key. Restart between placement and breaking: still no key. Restore normal chances afterward.
4. **Movement/generation:** Place a tracked block, push it with a piston, pull it back, then break it. Test adjacent moved blocks and falling sand/gravel. With exclusions enabled, generated cobblestone and a sapling-grown tree must not award keys.
5. **Protection:** Attempt mining inside a protected region without permission. Canceled breaks must award nothing and must not erase placed-block tracking. Confirm the protection plugin honors conventional event cancellation.
6. **Tools:** Test each PlexonTools multi-block tool. Blocks must emit normal break events; placed blocks must never roll. If event volume is too high for the intended economy, configure an activity cooldown or lower chances.
7. **Fishing/mobs:** Only successful item catches in open water should qualify. Verify spawner/egg/command/bred mobs are excluded by the default reason list, naturally spawned mobs qualify on a player kill, and player deaths never qualify.
8. **Claims:** Test an empty inventory, a completely full inventory, a partial stack with four spaces, and unstackable keys. Right-click claims one; left-click claims a category; claim-all fills available space and leaves the rest virtual. Spam clicks, close the menu before a click executes, and try shift/number/drag/double-click interactions. No decorative item should be obtainable.
9. **Bonuses:** With Vault plus your actual economy provider, enable a small Basic cash bonus and XP bonus. Earn one virtual key and verify exactly one payment of each. Claiming must pay neither again. Verify the documented warning/behavior when the provider is unavailable, then restore the provider.
10. **Announcements:** Earn each rarity; check only configured categories broadcast and that MiniMessage gradients/click actions render correctly. Check PlexonChats routing still behaves normally.
11. **Permissions/editor:** Confirm non-admins cannot use admin commands or menus. Revoke permission after an admin menu opens and before clicking. Test boolean toggles, numeric values, an inline world list, a MiniMessage lore list, prompt cancellation/expiration, invalid YAML, invalid material, and overlapping menu slots. Failed edits must keep working settings.
12. **Persistence:** Record balances and tracked positions, run `/keysadmin save`, stop normally, and restart. Then earn/claim without a manual save and repeat a normal `/stop`/restart. Confirm both shutdown and manual saves survive. Check logs for failed transactions.
13. **Crash policy:** Do not assume forced crashes are safe. Read the README's storage section and choose whether shutdown-only saving is acceptable. Optional checkpoints reduce the unsaved window but do not make inventory/Vault/SQLite updates atomic. Test any forced termination only on disposable staging data.
14. **Performance:** Profile real gameplay with your existing server tools. There should be no recurring PlexonKeys task with `checkpoint-seconds: 0`, no per-block SQL, and no chunk scans. Memory grows with tracked placements/player records; watch `/keysadmin status` on long-running build-heavy servers.

Keep backups of the database, configuration, worlds/player inventories, and economy data before making production changes.
